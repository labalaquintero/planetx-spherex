# Checklist manual de UI · 2026-11-14

**Ámbito: SIMULADO-manual.** Se recorre la UI a mano con `pnpm dev`. En desarrollo la app **no llama a la API**: usa el mock interno de Santiago (`web/src/features/viewer/api.ts`, retardo de 250 ms), así que esto **no prueba la API real, ni datos reales, ni la demo desplegada**, y la pestaña Network de DevTools **no mostrará peticiones** a `/api` (ni siquiera en las búsquedas válidas). Los resultados REAL se registran aparte (F01-R*).

**Estado: PLANTILLA SIN EJECUTAR.** Las columnas «observado», «pasa/falla» y «captura» están vacías hasta que la persona que recorre la UI las rellene. Lo «esperado» sale de leer el código del visor y de los criterios F01 (`docs/qa/aceptacion/F01-criterios.md`); no se ha verificado en pantalla.

## Preparación

1. Desde la raíz: `pnpm --dir web install --frozen-lockfile` y `pnpm --dir web dev`. Abrir `http://127.0.0.1:5173` (puerto estricto).
2. Anotar: SHA de la rama (`git rev-parse HEAD`), navegador y versión, sistema, fecha y hora, y quién recorre.
3. Las capturas se guardan **fuera de Git** y se citan por nombre en la última columna. No se suben vídeos ni capturas al repositorio.

## C. Coordenada inválida: el formulario no avanza

La comprobación real de «no se envía la petición» está en los specs `errores.spec.ts` (C09–C11), que requieren el build de producción.
